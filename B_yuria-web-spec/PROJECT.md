# PROJECT.md — 尤里亞的占卜計算器

## 1. 專案定位

建立一個「尤里亞最佳選牌決策引擎」網頁。玩家每回合輸入畫面上出現的 3 張候選牌，以及前面已選卡片的啟用/失敗結果，系統計算：

- 哪張牌的最終平均幸運分數最高。
- 哪張牌達成指定獎勵階段（例如 Lv.7 / 2700）的機率最高。
- 哪張牌的低分風險最低、分布最穩定。

核心不是用 LLM 猜牌，而是用遊戲規則、精確公式與 Monte Carlo / Expectimax 類決策方法運算。AI 僅作自然語言目標解析與結果解釋的可選層。

## 2. 成功標準

玩家能在手機遊戲旁，用 10~20 秒完成一次輸入並得到 3 張牌的排序、理由與機率。

MVP 驗收：

1. 可完整記錄最多 5 次選牌。
2. 可輸入每張卡的顏色與啟用/失敗狀態。
3. 下一回合 3 張牌輸入後，在前端完成至少 10,000 次模擬。
4. 顯示平均分數、P10/P50/P90、Lv.5/Lv.6/Lv.7 達標率。
5. 未驗證規則必須顯示「假設中」，不得偽裝成官方規則。

## 3. 建議技術

### 前端
- Vite
- React
- TypeScript
- CSS Modules 或 Tailwind（擇一，不混用）
- Web Worker：執行大量 Monte Carlo，避免 UI 卡住

### 儲存
- LocalStorage：MVP 儲存偏好與上一局
- IndexedDB：若要保存大量歷史局數
- Supabase：第二階段收集玩家匿名實測盤面，用於驗證未知規則

### 部署
- Vercel Static / SPA
- 若啟用 Jev：使用 Vercel Serverless Function 保存 `TYPESAFE_API_KEY`，不可放瀏覽器

## 4. 產品原則

- 數學先於 AI：可由公式確定的內容全部由程式計算。
- 顯示分布，不只顯示單一「推薦」。
- 可切換目標：平均最高 / 達標最高 / 穩定最高。
- 所有未知條件可設定、可追蹤、可回歸測試。
- 手機優先；桌機只是放大資訊密度，不改變核心流程。

## 5. 資料來源與可信度

參考：
- https://dv3ex.dv3ex3.workers.dev/yuria/
- 使用者提供的遊戲規則與遊戲幫助

目前參考站表示：
- 公式骨架為 `floor(SUM × MULT × (1 + RedBonus))`。
- 倍率卡採加總，不是彼此相乘。
- 失敗卡仍有最低 20 分。
- 被移除卡片不計分也不計顏色。
- 世界只複製已啟用分數卡的最高值。
- 色彩獎勵採當前級距，不累加前級距。
- 上述內容以 6 組實測盤面做回歸驗證。
- 太陽是否將自己算入「啟用卡數」仍未驗證。

因此正式頁面需有「規則可信度」標示。

## 6. 分期

### Phase 1 — 可用 MVP
- 卡片資料與公式
- 手動輸入選牌
- Monte Carlo 推薦
- 三種目標模式
- 機率分布與色彩狀態
- 規則假設警示

### Phase 2 — 精度提升
- 實測盤面回報
- Supabase 資料集
- 逐項驗證未知規則
- Future-offer 生成模型校正
- Expectimax / MCTS 與 Monte Carlo rollout A/B 比較

### Phase 3 — AI 輔助
- Jev 將自然語言目標映射為 typed objective
- AI 生成簡短人類可讀理由
- 不允許 AI 改寫數值結果

## 7. 不做的事情

- 不宣稱可預測伺服器 RNG。
- 不把 LLM/Jev 當作卡牌機率計算器。
- 不在 MVP 做帳號、社群、排行榜、論壇。
- 不需要商城式多頁架構。
